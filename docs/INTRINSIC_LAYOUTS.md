# Editable intrinsic layouts

Use **Auto row** and **Auto cell** for content-driven sibling widths, such as an icon beside a label or cards whose images and text determine their relative sizes. Unlike native Section/Group columns, these cells share one automatic table layout. Existing Table blocks remain rich-text tables and keep their current behavior.

An `IntrinsicRow` contains ordered `IntrinsicCell` blocks in `props.cells`. Each cell has an ordered `props.content` slot accepting ordinary Text, Image, and nested IntrinsicRow blocks. Text remains inline-editable; images retain their URL, upload, native attribute, selection, and undo controls. IDs are ordinary Puck IDs during editing. Import creates fresh IDs rather than trusting IDs from external source.

## Model and controls

```ts
const row = {
  type: "IntrinsicRow",
  props: {
    id: "contact-row",
    padding: "0px",
    width: "auto", // "auto" or "100%"
    mobile: "keep", // "stack", "two", or "keep"
    cells: [
      {
        type: "IntrinsicCell",
        props: {
          id: "icon-cell",
          padding: "0px 14px 0px 0px",
          verticalAlign: "middle", // "top", "middle", or "bottom"
          content: [
            {
              type: "Image",
              props: {
                id: "icon",
                src: "https://example.com/icon.png",
                alt: "",
                width: 16,
                padding: "0px",
              },
            },
          ],
        },
      },
      {
        type: "IntrinsicCell",
        props: {
          id: "label-cell",
          padding: "0px",
          verticalAlign: "middle",
          content: [
            {
              type: "Text",
              props: { id: "label", content: "<p>Contact us</p>", padding: "0px" },
            },
          ],
        },
      },
    ],
  },
};
```

Put the row in a normal column or Hero content slot. Row defaults are `width: "100%"`, `padding: "0px"`, and `mobile: "stack"`. Cell defaults are zero padding and top alignment. Both accept `cssClass` using the existing visual CSS-class syntax. They are safe HTML layout primitives, not new MJML component types, so they do not have native MJML attribute controls of their own.

EmailEditor's **Add or move blocks** controls support these static slots, including nested rows, cells, and ordinary Image/Text blocks. Existing permissions and read-only ancestor/descendant locks still apply. Raw blocks are never offered inside intrinsic cells, even in trusted HTML mode. As with pointer editing, an insertion can temporarily exceed the row's resource limits; the visible error and Undo behavior described below apply.

Below the document's MJML breakpoint, `stack` places one cell per line, `two` places two equal-width cells per line, and `keep` retains the automatic table row. Nested rows select their own mode. Breakpoint media rules use MJML's integer-pixel boundary, including its truncation of fractional pixel breakpoints.

An explicit Image width is the requested pixel width, not merely a natural-size cap: a 24px image requested at 64px grows to 64px when space allows. The image also has `max-width:100%`. Omitting its native width leaves sizing to the automatic table (`width:100%` on the image, without a numeric HTML width). To omit the usual visual Image width, set `{ name: "width", inherit: true }` in `mjmlAttributes`. Head/class defaults can then supply a width. Intrinsic sizing differs from ordinary MJML column image sizing; test unusually wide content in the compiled email and target email clients.

## Safe, editable MJML source

Export emits standard `mj-table` containing explicitly marked presentation tables, cells, and leaf wrappers. The content, links, image sources, and styles in the visible markup are authoritative. The importer recognizes only the versioned, structurally validated format generated by the exporter. It does not reinterpret arbitrary unmarked complex tables as editable layouts.

The optional `data-pm-origin` attribute contains bounded advisory inheritance hints, not a second copy of the content or a trust grant. Each hint binds an omitted native field to the emitted value using a SHA-256 digest. If that visible field is unchanged, its original omission and MJML class/default behavior survive import. A head-only change can therefore update inherited fields. A visible leaf edit releases that field's hint and becomes explicit. Hints contain no document IDs, raw HTML, URLs, or imported source blobs.

Deleting the hints materializes representable visible values. An image's exact generated `width:100%` without a numeric width remains the native width-omission exception. Removing a visible link or optional attribute produces an explicit empty override where safe. If an absent style cannot be represented without a head/class default silently restoring it, import reports unsupported markup instead of guessing. Native CSS class values follow the existing native validation rules.

Padding/border shorthands precede corresponding side declarations. Keep that order when editing generated CSS; overlapping declarations in reverse order, duplicate declarations, `!important`, extra wrappers, comments, or unsupported content are not accepted as the editable format. Rich text and native leaf attributes always pass their existing safe validators. Trusted raw HTML and template attributes are never supported inside intrinsic cells, even when the host enables raw HTML elsewhere.

Unsupported marked markup follows the existing Table raw-HTML fallback and trust requirements. Resource-limit failures instead stop immediately with an explicit error before general HTML parsing; they never downgrade to an unbounded raw parse.

## Limits and temporary editor states

Each outer row, including its `mj-table` wrapper, is limited to:

- 64 MiB of serialized UTF-8 source, including assets.
- 256 layout/leaf blocks, eight nested row levels, 4096 HTML tokens, and 64 HTML nesting levels, including rich text.
- 64 KiB per ordinary text/attribute value.
- 8 KiB of decoded inheritance metadata and 48 KiB in its encoded attribute.

The existing local-image opt-in and 5 MiB raster upload limits still apply independently. A row can hold several full-size allowed uploads within the aggregate budget. Image data is not duplicated in metadata. Unchanged validated assets are reused during adjacent text edits without repeatedly decoding or hashing them.

Uploads are checked against the latest owning row before their result is accepted. Manual URL typing can pass through an invalid intermediate value, as with other editor fields. Dragging, duplication, or host edits can also create a temporary invalid row. The canvas shows an error; source export fails clearly until the document is corrected or undone. No content is silently truncated and history is not rewritten. Oversized/deep subtrees are not rendered while invalid.

The canvas uses valid CSS-table `div` elements through public Puck slots. Compiled email uses actual presentation tables. Generated responsive sheets are recognized only when they match the entire deterministic sheet; repeated imports do not accumulate them, and modified authored CSS remains intact.
